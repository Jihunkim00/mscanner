# PR19 — 나의 미식 여행

작업 브랜치: `agent/pr19-my-food-journey`

검증일: 2026-11-03 (한국 시간)

## 구현

- 기존 홈의 인기 메뉴 캐러셀 아래에 미식 여권과 미식 DNA를 묶은 카드 하나를 추가했다. 검색, 최근 좋아요, 사용 방법, 광고, 주변 리뷰, 하단 5개 탭은 유지했다.
- 홈에는 국가 수, 최대 세 국가의 국기, 가장 많이 탐색한 음식 유형과 비율을 표시한다. 한국어 기본 크기 렌더링에서 카드 높이는 약 146dp이며, 좁은 화면이나 글자 확대에서는 세로로 늘어난다.
- 상세 화면에는 국가별 저장 횟수와 첫/최근 저장 날짜, 상위 세 음식 유형, 전체 여덟 유형의 막대 차트와 미분류 수를 표시한다.
- 빈 기록, 분류 불가, 비동기 로딩, 오류/재시도, 캐시 표시, 당겨서 새로고침을 지원한다.
- 기존 `AdaptivePage` / `AdaptiveContent`를 사용하며 넓은 화면에서는 여권과 DNA를 나란히 배치한다. 다크모드, RTL, SafeArea, 글자 확대, 리사이즈를 지원한다.
- 22개 UI 로케일의 ARB와 기존 두 로컬라이제이션 생성 경로를 갱신했다.

## 데이터 범위와 정확성

Firestore는 `user_rating/{uid}/data`만 읽는다. `user_data`를 합산하거나 과거 삭제 기록을 복구하지 않는다. 기존 History와 같은 `timestamp` 내림차순을 사용하고 문서 ID를 추가 정렬 기준으로 사용한다.

무료 사용자는 `HistoryRetentionPolicy.freeHistoryLimit`를 그대로 참조해 최신 최대 20개만 읽으며 추가 페이지 요청도 차단한다. 프리미엄은 홈에서 50개를 집계하고 상세 화면의 버튼을 눌렀을 때 다음 페이지를 읽는다. 다음 페이지 존재 여부를 확인하기 위해 요청당 최대 51개를 읽고, 확인용 한 개는 현재 집계에 넣지 않는다. 커서는 실제 집계한 마지막 문서에 둔다. 부분 조회 중에는 최신 조회 기록 수와 추가 기록이 있다는 문구를 표시한다. 전체 평생 누적 통계로 표현하지 않는다.

국가명은 ISO 3166-1의 249개 코드와 Node Intl/ICU CLDR에서 얻은 22개 로케일의 이름, 일반적인 별칭을 정확히 대조한다. `country`가 우선이며, 없으면 저장된 `city`/`other`의 명시적인 국가명만 보조적으로 읽는다. 빈 값·미확인 이름·상충하는 보조 국가명은 제외한다. 자유 형식 위치 설명의 두 글자 코드는 주/도시 약칭일 수 있어 사용하지 않는다. GPS, geohash, 앱 언어, 현재 위치로 방문 국가를 추정하거나 역지오코딩 API를 호출하지 않는다. 날짜를 확인할 수 없으면 날짜를 만들어 표시하지 않는다.

DNA 대표 메뉴의 우선순위는 `recommended[0]` → `primary_menu` → 구버전 `items[0]` 또는 명시적으로 번호가 붙은 첫 메뉴다. 기존 `ResultParsingService`의 JSON 추출 및 메뉴명 정리 함수를 재사용한다. 문자열 응답 목록, 구버전 단일 응답, 코드 블록, 여러 JSON 객체, 잘못된 JSON, 빈 값, 일반 텍스트를 안전하게 처리한다. 레스토랑 이름을 음식으로 취급하지 않는다.

음식 분류는 다국어 요리명 사전, 음식명에 있는 명시적인 유형, `shortDesc`/`tags`의 단서 순으로 판정한다. 구체적인 요리명은 재료보다 우선한다. 예를 들어 해산물 라멘은 면, 치킨 볶음밥은 밥, 초밥은 해산물이다. `category`, `rating`은 음식 유형이나 선호도 점수로 사용하지 않는다. 불확실한 항목은 `unknown`으로 둔다.

문서 ID를 중복 제거하고 멀티 스캔도 한 문서당 최대 한 점만 부여한다. 미분류는 DNA 분모에서 제외한다. 정수 퍼센트는 나머지가 큰 유형부터 반올림 잔여치를 배분해 분류된 비율의 합이 100%가 되도록 한다. 음식에 대한 호감이나 실제 섭취를 추론하지 않는다.

## 읽기 비용과 캐시

- 영구 저장 없이 세션 메모리 캐시를 사용한다. 키는 버전, UID, 프리미엄 여부로 구분하며 유효 시간은 5분이다.
- 같은 계정/권한 범위의 진행 중 요청을 공유한다. 홈 재구축 때 전체 이력을 재다운로드하지 않는다.
- 계정 전환/로그아웃 시 기존 계정 캐시를 지운다. 늦게 도착한 응답은 요청 세대 번호로 무시한다.
- 홈에서 저장이 성공하고 기존 보존 정책 처리가 끝난 뒤, 또는 History에서 삭제가 성공한 뒤 캐시를 무효화한다. 삭제된 기록을 오류 시의 캐시로 다시 보여주지 않는다.
- 네트워크 오류 시 사용 가능한 메모리 캐시와 안내/재시도를 제공한다. 새로고침 실패와 추가 페이지 실패를 구분해 해당 요청을 재시도한다.
- 이미지 URL을 이용한 다운로드, 새 AI 호출, 실시간 전체 이력 구독, 새 Firestore 집계 문서가 없다.

## 변경 파일

`lib/features/food_journey/`에 다음 9개 파일을 추가했다.

- `models/food_journey_summary.dart`: 저장 문서, 국가 스탬프, 음식 유형, 비율 모델.
- `services/country_names.dart`: 오프라인 다국어 국가명 데이터.
- `services/food_passport_service.dart`: 국가 정규화와 여권 집계.
- `services/food_dna_classifier.dart`: 대표 메뉴 파싱과 음식 분류.
- `services/food_journey_repository.dart`: 읽기 전용 Firestore 페이지 조회.
- `services/food_journey_service.dart`: 집계, UID/권한별 캐시, 요청 및 무효화 관리.
- `widgets/food_journey_home_card.dart`: 홈 카드와 기존 인증/구독 상태 연결.
- `widgets/food_journey_sections.dart`: 여권/음식 DNA 상세 위젯.
- `screens/food_journey_screen.dart`: 상세 화면과 추가 페이지/새로고침.

기존 코드 수정은 `lib/screens/Home_Screen.dart`의 카드 삽입·저장 후 무효화, `lib/screens/favorite_list_screen.dart`의 삭제 후 무효화, `lib/l10n/`의 ARB 및 생성 파일이다. 신규 테스트는 여권, 음식 분류, Repository, Service, 홈 카드, 상세 화면의 6개 파일이다.

사용자가 미리 변경한 `pubspec.yaml`의 `1.3.46+159` 버전은 보존했다. 새 패키지를 추가하지 않았다. Firebase Functions, AI 계약/프롬프트, Firestore 스키마, HistoryRetentionService, 네이티브 Android/iOS 파일, 광고/결제/게스트 정책에는 변경이 없다.

## 미검증 및 PR20 후보

Windows 환경이므로 Xcode/iOS 빌드 및 iPhone 실기기 실행은 검증하지 않았다. Android 실기기·실제 폴더블의 접힘/회전, 실제 Firebase 계정의 보안 규칙·온라인/오프라인 전환, 카메라·광고·인앱결제의 종단 간 동작은 별도 확인이 필요하다. Repository 테스트는 주입한 조회 어댑터를 사용하며 실제 Firestore 서버나 에뮬레이터 통합 테스트는 아니다.

PR20에서는 실제 보유 데이터로 국가 별칭·음식 사전의 오분류를 점검하고, 번역의 원어민 검수, Firebase 에뮬레이터 통합 테스트, iOS/폴더블 실기기 검증을 추가하면 좋다. 세션을 넘어선 요약 캐시가 필요해지면 계정 격리와 삭제 무효화 정책을 유지하면서 별도로 검토할 수 있다.
